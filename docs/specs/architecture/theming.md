# テーマ（Pico.css + CSS 変数）

## 原則

1. **スタイルのベースは [Pico.css](https://picocss.com/)** とする
2. **カラーテーマの差し替えは CSS 変数**で行い、サイトごとに上書きしやすくする
3. 利用側は変数上書きを基本とし、コンポーネント実装のクラス構造や DOM 詳細への依存は推奨しない

## スタイル層

```
Pico.css（ベース）
    ↑ 変数で色・系を差し替え
hermit-crumb デフォルトトークン（module が提供）
    ↑ サイトごと上書き
利用側の CSS 変数上書き
```

| 層 | 責務 |
| --- | --- |
| Pico.css | リセット相当・タイポ・フォーム・レイアウトのベーススタイル |
| パッケージ | Pico を module 経由で読み込み、ドキュメント向けのデフォルト変数セットを定義 |
| 利用側 | サイトブランドに合わせたカラー変数の上書き（推奨カスタム） |

## パッケージの提供物

- Pico.css の依存／取り込み（バージョンは v0.1.0 実装時に固定し、`doc-site` 依存方針と同様に明示する）
- カラーテーマ用 CSS 変数のデフォルト定義（ライト／ダーク。`@nuxtjs/color-mode` と連携）
- Pico のカスタムプロパティと整合するトークン命名（可能な範囲で Pico 公式の theming 慣習に寄せる）
- ドキュメントシェル固有の追加変数（必要最小限。例: サイドバー幅やヘッダー高さなど——色以外は最小）

## サイトごとのカラー差し替え

利用側は次のいずれか（または併用）でカラーテーマを差し替える。

1. 生成プロジェクトの CSS で `:root` / `[data-theme="light"|"dark"]` 等に変数を上書き
2. create 時に用意する「テーマ上書き用」の薄い CSS ファイルを編集（所有物）

目標は、**コンポーネントを触らずに色だけ差し替えられる**こと。

## 利用側のカスタム手段（優先順）

1. **CSS 変数の上書き**（推奨・主契約。とくにカラー）
2. 生成された UI コンポーネントの直接編集（所有物として）
3. slots / 薄いラッパでの差し込み

## 非目標（v0.1.0）

- Pico を使わない独自ユーティリティ CSS フレームワークの導入
- 生成 CSS ファイルの大改修を主経路にすること
- 実行時に任意パレットを組み立てる高度なテーマエンジン（変数上書き以上のもの）

## semver との関係

| 変更 | 想定バージョン |
| --- | --- |
| カラー変数の追加（後方互換） | minor |
| 変数の削除・意味変更、Pico メジャー切り替え、デフォルト見た目／クラス構造の大きな変更 | major |
| トークン値の微調整（コントラスト修正等）で契約名が変わらない | patch または minor（影響範囲で判断） |
